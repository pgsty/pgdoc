# PostgreSQL 中译风格

准确 > 一致 > 流畅 > 本土化润色。

## 术语

- [exclude.tsv](exclude.tsv) 中的术语保留原文；其余按 [glossary.tsv](glossary.tsv) 的英文、中文两列处理。未收录时遵循本规范和相应上下文的稳定译法。
- 具体译名以词表为准，本文件不重复词表已有内容。不要因个人偏好替换 PostgreSQL 社区历史译法；发现明显错误时核对英文后修正，并更新术语表。
- 词表未收录的 `archive` 译为“归档”，`worker` 依上下文使用“工作者”或“工作进程”。
- 主备复制语境中的 `standby` 按角色翻译；泛指待命或备用状态时可用“后备”，不要机械套用角色译名。
- 新术语定稿后补入 `glossary.tsv`，术语变更记录到同目录的 `change.md`。

## 文体

- 使用正式、克制的技术说明文体，保留原文的定义、约束、例外和交叉引用顺序。
- 贴近英文信息结构，仅为可读性做必要调整；不主动拆散或重组段落，不添加原文没有的背景、类比和解释。
- 同一概念复用固定译名，避免在不同章节换成解释式同义表达。
- 首次出现可沿用“中文（英文/缩写）”的引介方式，后续使用固定译名或缩写；保留 `SQL`、`MVCC`、`WAL` 等通用缩写。

## 保留原文与标点

以下内容的字面形式保持原样：

- SQL 命令、关键字、子句和 `psql` 元命令。
- 程序、工具、扩展、模块、类型、函数、运算符、配置项、系统视图、系统目录和其他对象的名称。
- 文件名、路径、环境变量、选项、错误码和协议消息名。
- 代码块、SQL 示例和命令行示例中的标识符。

正文使用中文全角标点；代码、命令、配置、路径和标签属性中的半角标点保持原样。

## SGML

翻译只修改可翻译文本节点，保留标签、属性、层级、`id`、`linkend`、实体引用，以及内嵌代码、交叉引用、索引和命令参考页结构。上游差异要求的结构或示例变更另行同步。
