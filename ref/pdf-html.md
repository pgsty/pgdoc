# PDF / HTML 排版修复与验收

本流程补充 [acceptance.md](acceptance.md)，不替代对应版本英文和译风规范。按任务范围构建；共享工具变更须验证两条管线，不自动扩大到所有版本正文。

## 修复边界

- 排版问题在样式或构建后处理中解决；正文错译、缺字和真实术语问题按固定英文最小修正。不要为了绕过排版故障改写正确的源文。
- HTML 修改文本区间，保留标签、属性、实体拼写和受保护内容。实体可解码来判断相邻字符，但不能把原始 `&gt;` 的分号当中文标点。URL 中的实体同属 URL，不能先分割实体再修改查询参数。
- 排版后处理只调整空白和断行，保留正文标点。普通正文也可能包含 `#:`、`#,`、格式分隔符和带引号的返回值，不能仅因相邻中文就替换符号。
- PDF 字体选择只影响呈现，不能消除代码保护。等宽字体继承至嵌套节点；中文字体置前时保留等宽字体的后备声明。
- 行、示例和脚注按 FOP 的实际高度判断是否完整排版，超过可用页高时允许拆分。`always` 不能作为所有表格行的默认保留规则；源代码换行数也不等于实际折行数。测量探针使用固定保留条件，不能继承上一次校准结果。参考条目的语法块须同时计入“大纲”标题和间距，避免仅代码能放入整页却把条目标题孤立在前页。示例前导段落应与其示例尽量同页；不超过 100pt 的末节、最后两段、末尾列表项、短定义列表和末尾提示框与前文相连。页眉应给长命令名足够宽度，不能只检查正文和页脚。

## 验证顺序

1. 冻结输入、备份现态、记录版本身份和哈希，保留无关修改。
2. 对每个内容回归加入可复现用例，覆盖完整处理流程。比较节点、链接、实体、属性和保护区，不能只检查某个内部函数。
3. 对整本 FO、全部 HTML 重复执行完整后处理；第二遍的文本、属性和结构须稳定。检查已修位点及代码字面内容，不能因幂等就认定第一次没有改坏。
4. 实际重建 A4、US 和 HTML，记录退出码与完整日志。独立检查链接、资源、书签、字体缺字和正文边界。FOP 的错误、缺字、溢出须核查；退出成功不代替验收。
5. HTML 使用 `bin/check_rendered_html.py` 检查真实行内文本。该检查器不导入规范化代码；代码与 URL 受保护。把标签替换为空格会遮蔽 `使用<a>PostgreSQL</a>数据库` 这类缺陷。空格候选须裁定，结构或保护错误必须解决。
6. PDF 对机器候选进行图像复核，重点检查页脚、表格跨页、短示例、节标题、窄列、索引和长标识符。记录物理页和印刷页，并绑定该次产物哈希。HTML 在浏览器中复核桌面与窄屏的代码、表格和图示；宽表格可局部滚动，不能靠极小字号掩盖溢出。
7. 源文修订保留英文引文、原中文、新中文、完整上下文和理由；旧报告的数量和结论不直接继承。修复、误报、合法保留、源文疑义分别记录，交付不得藏匿未决缺陷。

## 已复现判例

- synopsis 的子节点尾文本误写回父节点正文，会覆盖开头并重复说明。尾文本必须写回对应子节点；测试必须验证整句内容。
- 正则 `<[^>]*>` 不能识别属性中的 `>`，会让后续规范化改写属性；SVG、MathML 和脚本也须完整保护。
- 函数签名已有空白时继续追加空白，会让完整 FO 二次处理不幂等。
- 中文等宽节点改成纯中文字体后，第二次处理可能把语法字符串的直引号变成弯引号。
- 无条件保留 JSON_QUERY 的超高表格行，可在 US 页脚处溢出；实测高度后，对超高单元使用 `auto`，可容纳的单元使用 `always`。有限保留强度也可能把长语法块的节标题单独推到一页，须复核实际产物。
- FOP 2.11 在嵌套列表的弹性段间距中可能把正文绘制到页脚而未报错。PG18 对照实验保留原最佳间距，将已有最小、最大值固定为最佳值后消除了越界；不应仅靠整段保留或增加留白掩盖问题。
- 长段落内的引导句可与后续代码分开；定义列表、带标题的步骤和普通说明也可能出现同类分页。只调整保留属性，按原生布局测量引导句及首项高度，并验证两者的实际页码。旧版 DocBook 段落可能没有显式孤行属性；函数表中的紧凑说明也会覆盖普通段落属性。须结合实际段落样式和直接行内正文识别，不能把外层包装当作段落，也不能把零检出当作零问题。识别可见正文时忽略无宽度的断行控制字符，保留实际排版数据中的原字符，避免冒号后的控制字符遮蔽引导句。段落末尾引出下一组内容时，只计入末尾引导句；同时检查先前段落、首项标题和内容形成的整条保留链，过长时放松段落保留，不能用新的绑定掩盖溢出。
- PG18 A4 索引中一个标识符在 10pt 时宽 220.27pt，超过 219.637pt 列宽；仅该版本索引字号调整至 9.5pt，标识符保留原文。字号修改仍须复核实际最窄列，不能忽略超宽告警。

具体实验版本和一次性日志放在任务证据目录；这里保留适用边界，避免把某次 FOP 实验写成永久禁令。
