# 任务流程：跨大版本迁移（新建大版本中文 / 旧版归档回填）

两种变体共用"固定源码 → 完整差异 → 结构迁移 → 复用优先 → 增量翻译 → 构建验收"的骨架，分两个阶段执行：

- **正向迁移**：以已校版本的英文+中文为基线，生成新大版本 `zh/<新>/`（先例：zh/20 从 zh/18.6 迁移）。主差异始终是 `旧基线英文 → 新目标英文`，不能改成比较邻近版本。
- **反向回填**：以最新已校版本为共同底稿，回推旧归档版本（先例：PG10–13 从 PG14.24 回填）。四条主差异各自从同一份基线英文出发（14.24→13.23、→12.22…），**不逐版串接**，不把刚生成的某版中文整树当下一版底稿。

## 第一阶段：准备（固定输入、底稿、完整 diff）

### 1. 固定可复现输入

- 记录 Git HEAD、工作区状态、中文基线与规则文件 SHA256；复制到本轮独立快照并核对无漂移。**中文基线取当前工作区**（含人工修改），不从 Git HEAD 导出替代。
- 正向迁移取新版本源码：正式版用官方包+SHA256；devel 版必须**固定完整提交 SHA**（官方 Git 或 GitHub 镜像），核对版本声明（如 `20devel`），记录提交/下载时间；不能把分支 HEAD 当固定快照持续追随。目录名（如 `en/20/`）与版本串（`20devel`）分开记录。
- 反向回填取各旧版最后小版本的官方发布包并核验；发布包以真实包身份为准，不虚构 Git 提交。

### 2. 初始化中文底稿

从冻结的基线中文复制源文件、图片、项目中文样式与构建配置到目标 `zh/<目标>/`。按实际 Makefile 依赖排除 HTML/PDF/FO、展开 XML、缓存等生成物（不能仅凭扩展名判断）。逐文件记录来源与哈希。此时**不翻译**；底稿状态写入记录，不把继承内容当成交付。

### 3. 递归盘点 + 完整差异

全树比较（含子目录、图片、实体、样式、脚本），交付：

| 文件 | 内容 |
|---|---|
| `source-manifest.json` | 固定的英文/中文/规则输入及校验信息 |
| `inventory.tsv` | 全部路径、类型、旧/新哈希 |
| `changes-summary.tsv` | 每文件动作、增删行、hunk 数、分类 |
| `full.diff` + `diffs/` | 完整原始差异与逐文件 diff（新增/删除文件也要有原文证据） |
| `hunks.tsv` | 块 ID、行范围、SGML 锚点、分类 |
| `structural-map.tsv` | 重命名/搬移/拆分/合并的来源→目标映射及证据 |
| `translation-units.jsonl` | 语义单元：关联 hunk、旧/新英文、可复用中文、状态、处置 |
| `baseline-issues.md` | 基线原有缺文、错配、未决问题（单列，不伪装成新版本差异） |

自检路径等式：旧文件总数 = 不变 + 修改 + 删除；新文件总数 = 不变 + 修改 + 新增。用重命名展示时另保留原始路径分类。

### 4. 结构迁移与译文复用

- 新增路径先查是否为旧文件重命名/拆分/搬移（先例：`func.sgml` 拆为 `func/` 子树）。为每个搬移片段建立 `旧英文锚点 → 新英文锚点 → 基线中文片段` 映射；旧文件删除前先保存可复用中文。
- 未变化的搬移内容直接沿用原译，只有片段内部新差异进入翻译；已有文件的新增段落、新路径中的旧章节也要检索历史译文。
- 参考其他现有版本译文时，先确定其对应英文快照并与目标片段对齐；不整树复制邻近版本取代基线。

## 第二阶段：生成专用执行提示词并执行

1. 依据实测结果生成本轮专用提示词、`TASKS.tsv`（任务 ID、批次、依赖、目标文件、动作、关联单元、中文来源、旧/新英文、状态、验收要求）与 `PLAN.md`。**填入实测 SHA、统计、文件清单，不留"待填"占位符**；有真实阻塞就明确报告，不伪造可开工状态。
2. 动作分类（文件与语义单元可分层）：`copy_unchanged` / `relocate_or_split` / `delete` / `update_structure` / `translate_new_content` / `translate_changed_content` / `sync_literal_or_resource` / `regenerate` / `retain_project_customization` / 基线未决。删除限目标版本确实不再存在的内容，同步包含链、索引、交叉引用。
3. 以目标版本原文决定最终技术事实与结构；英文变化的代码与名称原样同步。同英文语义单元跨章节/跨版本复用同一译文；不为新版本特性回改旧版本。
4. 涉及同一文件或同一术语族的任务协调批次，避免相互覆盖与各自定译法。

## 反向回填的差异语义表（左侧=基线英文，右侧=目标英文）

| 英文路径关系 | 目标中文处理 |
|---|---|
| 两侧相同 | 原样复用基线中文，保留人工格式 |
| 仅基线有 | 从目标底稿移除；先确认是否存在于目标其他位置 |
| 仅目标有 | 恢复历史内容；先检索可复用译文，无基础才首次翻译 |
| 均有但不同 | 以目标英文为准局部回推，保留共有部分中文 |
| 重命名/搬移/拆分 | 先映射保存中文片段，再按目标结构迁移 |

"新增"不等于新功能（反向比较中可能是后来被移除的旧功能）；文件不存在不证明内容不存在，ID 相同不证明正文未变。

## 验收

- 目录与包含链符合目标版本；hunk 与语义单元全部有可核查处置；未变化中文可用来源/哈希/片段映射证明复用。
- 术语、SGML、ID、链接、代码、数字逐项核对；构建目标版本中文 HTML + A4 PDF + US PDF（同一份固定源码），核对显示版本号正确。
- 抽查新增页、变更页、结构迁移页、目录/索引与 PDF 中文字体；修改公共构建脚本时保持旧版本调用兼容并针对验证。
- 交付：完整 diff、动作与翻译台账、构建证据、基线问题、确切未决项。不提交、推送、发布（须用户指令）。

## 判例

- **`func/` 拆分布局**：根目录 `func/func.sgml` 是简介存根，队列与探针必须聚合 `func/` 目录实际文件，严防存根遮蔽目标文件。
- **devel 构建脚本陷阱**：现有脚本可能查询开发分支/用缓存 snapshot，须用显式 `PGDOC_SOURCE_DIR`+`PGDOC_SOURCE_COMMIT`（或 archive+SHA256）固定；不能只凭版本参数声称已固定。
- **发布说明**：按每版真实源码及包含链处理，不把基线版本发布历史改标题沿用；目标手册自带的更早历史记录属于该手册。
- **项目 Makefile/中文 CSS/XSL 定制单列**，不混入正文翻译清单，也不被上游文件覆盖。
- **回填方向**："仅基线有"的内容删除前先全树检索目标位置（章节可能挪动而非消失）。
