# 任务流程：独立验收（与修复落地）

对修订/校准后的文档组织独立、完整、可追溯的验收；门槛满足时由主 Agent 统一落实修复。与 [full-review.md](full-review.md) 的区别：验收可含修复落地，且明确核验上一轮修改。

## 1. 范围与原则

1. 全部版本、全部正文在范围内（含已修改文件中的未改段落）；不受旧增量任务"只处理英文 diff"限制，但修订遵守最小必要改动。
2. 技术含义以**该版固定英文及其上下文**为准；不以新版知识判旧版忠实译文有错；不为跨版本统一把新功能/默认值/限制写入不适用旧版。
3. 质量顺序**准确 > 一致 > 流畅 > 本土化润色**："雅"是正式克制的技术说明文，不是文学化改写。
4. **不预设错误数量**：不为体现工作量制造润色；已正确且合规的段落判为可保留。
5. 旧报告的 `FIXED`/`reviewed`/`GO`/机器退出码/构建成功都是**待核对证据**，不能直接继承为结论；旧问题也不能因曾出现在报告就认定仍存在。
6. 不调用通用翻译 API 批量重译，不拼接网上现成中文。技术疑义读本地同版完整英文，必要时核官方源码并留来源；英文自身疑似有误时单列源文疑义。

## 2. 开工输入

1. 读取并记录哈希：`AGENTS.md`、顶层与各版 Makefile、`docs/` 全部规则文件、`docs/doc-alignment.md` 与 `bin/` 检查工具、构建脚本。
2. 重组装时的版本映射（本地 en 目录 ↔ zh 目录）逐一实测核对版本声明与来源；不以 `en/current`、`zh/current` 或分支 HEAD 决定验收版本。
3. 冻结快照；**审读阶段子 Agent 不写 `zh/` 正文**，正式修改由主 Agent 统一组织。
4. 子 Agent 共用上下文：规范完整文件及哈希、SOP、版本身份、分片、问题库当前修订号；每位子 Agent 必须确认已读适用规范，不依赖口头摘要。长词表分批完整加载，具体用例须检索完整词条。

## 3. 修改门槛与修复纪律

- **门槛**：经充分复核、确实优于现有译文才落改；每处修改能说清"从 X 改成 Y"及英文依据。可复用相邻版译文的指明母本版本。
- **防回归**：每轮修复必须实际写盘并复读验证（只改内存不落盘会被后续轮覆盖）；新反馈先复扫上轮已修项再处理新项。
- **证据对应**：修改处的英文引文必须取自本版真实连续子串（行号 = 引文起始行）；同一英文句代表多处位点被撤回过——共用引文须逐 site 重配。
- 不回退用户已有裁定（如已确认的九项术语回退）；不为个人偏好重开已裁决事项。发现真实规则冲突建疑义，不自行挑有利规则。

## 4. 验证

1. 结构与链接独立检查（构建放宽了中文 IDREF 校验，HTML 构建成功不代替检查）。
2. 实际构建各版 HTML + A4 PDF + US PDF；记录命令、退出码、日志、产物路径。
3. 抽查代表页面：标题、正文、目录、索引、表格、代码、中文字体渲染；PDF 对比既有 FOP 诊断无新增/加重。
4. `check-deps` 通过不是构建成功；构建失败定位首个根因如实记录，不因缺依赖跳过内容审计。

## 5. 交付

问题库（全量、带横向矩阵）、已落实修改的台账（修改前后、英文依据、验证结果）、构建证据、未决项与源文疑义。明确区分审读/修改/构建/发布四种状态；不自动提交、推送、发布。

## 判例

- **selfcheck/audit 0 错不能证明语义正确**：互换（如 `<<=`/`>>=` 含义颠倒）、截断、误删三类语义错机械校验全盲，须逐项人工复核。
- **同物理文件多 finding 叠加**：按 stage 现态匹配位点，防止前一轮修改被当作后一轮的"旧文本"。
- **修复范围纪律**：授权扩展逐项核定，不顺手批量清理授权外位点；撤回非核定段的修改。
- **回放与重建**：整文件重建时以 before 为基底做变换，不用 replace 丢字；8 文件级重建恢复先例成立。
- **多处同文逐处唯一化**：raw 行缩进区分 + 改后重读防重叠编辑。
