# 任务流程：全量精读审校（只审不改）

对单个（或多个）版本做全量逐句中英对照审读，产出结构化 findings 与横向矩阵。**只读审校：不回写正文、不改规则、不执行修复**——发现问题本身就是交付。

## 变体：逐文件评分校准

`docs/calibrate.md` 是历史实例：按文件维护"状态×评分"表（粗翻 30 分起步，多轮校对至 90+），每文件出一份校准报告（覆盖段落、发现分类、修改建议）。评分与"已校对"状态只反映当时轮次，**不能作为后续任务的质量或覆盖证据**。

## 1. 冻结与运行目录

1. 运行目录 `outputs/<review-task>-<run-id>/`（$RUN），写入即限于此。
2. 冻结快照：`$RUN/snapshot/zh/<版本>/` + 固定英文 `en/<版本>/`。工作树可能被并发会话修改，**一律以快照为准**；漂移只在收尾 `diff -rq` 只读记录。
3. 记录规范文件（`docs/`）哈希。质量判断依据：`exclude.tsv` > `glossary.tsv` > `style.md` > 既有稳定译文。

## 2. 构建阅读队列

解析快照为有序单元（句 / 表行 / 列表项 / 代码块与输出值），每单元含 file / en_line / zh_line / tag / en / zh。文件优先级参考：`func` → `config` → `libpq` → `monitoring` → 其余按文件名字母序。配套 cursor 文件支持断点续作（批次区间、verdict、findings 引用）。

## 3. 分批逐句判读（约 80 单元/批，循环至队列耗尽）

重点：**语义级错配**（否定、因果、条件、主体颠倒、数值、单位、方向、版本号）、**术语**（按词表）、**结构**（表格逐格、列表逐项、代码逐字）。

**疑似偏差必须先 grep 快照原文核实再定论。** 已确认的提取伪影与误报教训，核实后按 PASS 记录、勿误报：

- listitem/para 双计导致相邻单元配对偏移；重复样板键错位；xref/function 等内联元素被提取器剥离造成"缺链接"假象。
- EN 侧跨行折行导致 grep 漏配（探针用短语而非整句）；`<term>` 内容独占一行；实体转义（`&lt;`）改变字面量。
- **同构结构须分窗**：information_schema 相邻同构视图的同名列必须按 `sect1 id` 分窗比较，禁止拿上一视图的字段描述对照下一视图的 EN。
- **拆分布局存根遮蔽**：`func/func.sgml` 是简介存根，队列与横向探针必须聚合 `func/` 目录实际文件。
- 中文直引号→弯引号属合法本地化；EN 直引号对应的弯引号不是缺陷。标签丢失才是缺陷。

## 4. findings 协议（新问题落地）

每个新建 F-xxx 完整执行：

1. 字段齐全：id / title / category（P1 事实错误 | P2 语义或结构 | P3 措辞）/ severity / confidence / origin（PREEXISTING | INTRODUCED | UNKNOWN）/ en_evidence + zh_evidence（**双方行号 + 原文摘录；引文字节级拷贝不 strip**）/ issue / suggestion（明确"从 X 改成 Y"）/ cells（逐版状态）/ verify（grep 验证命令）。
2. **横向取证**：按根因写探针，对各版快照逐版 grep 取行号证据，EN 侧对照定界，判定 ❌ 存在 / ✅ 正常 / ➖ 不适用，写回矩阵台账。
3. 报告追加小节：具体情况与文件、逐版矩阵表（版本|结果|证据含行号）、严重程度/置信度、建议方案（可复用相邻版译文的指明母本版本）、修改理由。

**去重三关**（新发现先过）：按根因/模式比对（不看行号看本质）→ 已知且矩阵标该版存在 → 跳过（可补精确行号）；已知但矩阵标正常/不适用而实读确实存在 → 矩阵修正（不新增编号）；三关皆过 → 新建编号顺延。

## 5. 收尾

cursor 置完成标记（总单元数/批次数/新增清单/矩阵修正清单）；漂移只读记录；产出完成报告：覆盖量、新增问题摘要（每条一句+受影响版本）、矩阵修正清单、与已知问题的边界判定案例、未验证项。

## 判例

- **"与 EN 一致"不能证明免审**：图例、表格等即使与英文结构相同也要独立审内容。
- **机器核验 ≠ 阅读验收**：锚点全项核验、blob 归位等程序化检查不能替代逐句判读。
- **缺陷定位用 hunk + 旧原样行 + 双 SHA**，不用当前首命中代替（工作树可能已漂移）。
- **只审不改**：git 证实工作树零修改是验收条件之一；发现问题回写正文会使证据失效。
- **词中 vs 行尾**的不可见差异（空白折叠）分报，引文保留证据字节。
- 旧 blob 可经 `baseline_blob_verified`（git 提交）取回时 SHA 吻合，"HEAD 不等 = 不可复原"不成立。
