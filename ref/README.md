# 可复用任务流程（ref/)

本目录存放从 2026-09 各轮实际任务（PG20 迁移、PG10–13 回填、术语校准、逐版全量精读、全量验收、31 版结构 sanity check）中提炼的可复用任务流程与判例。一次性执行回执（校准报告、运行台账、清理记录）已清理；本目录与 `docs/` 规则文件是保留下来的方法资产。

| 新建大版本中文（如 zh/20 从 zh/18 迁移）、旧版归档回填 | [major-migration.md](major-migration.md) | 两阶段：固定源码+完整差异 → 生成专用执行提示词 |

## 翻译规则文件（docs/，随仓库版本管理）

| 文件 | 用途 |
|---|---|
| `docs/style.md` | 译风规范（准确 > 一致 > 流畅 > 本土化润色） |
| `docs/exclude.tsv` | 不翻译词表，优先级最高的译法约束 |
| `docs/glossary.tsv` + `docs/glossary.rules.tsv` | 术语表与逐条语境规则，必须配套使用 |
| `docs/glossary-aliases.tsv` | 仅用于检索、消歧和追踪旧译，不是替换字典 |
| `docs/terms-to-preserve.tsv` | 具体字面保护与适用语境 |
| `docs/change.md` | 术语与规则变更记录；每次规则调整在此登记 |
| `docs/calibrate.md` | 逐文件校准评分表的历史实例（文件×状态×评分格式） |
| `docs/doc-alignment.md` | 对齐检查器的完整使用文档 |

**译法判断顺序**：该版英文语义 → 字面保护（exclude.tsv / 保护区）→ 词条与逐条规则（glossary + rules）→ 译风与稳定现有译文。

## 所有任务共用的纪律

1. **固定输入。** 开工记录 Git HEAD、工作区状态、关键输入 SHA256；任务期间使用冻结快照，不追随并发漂移（漂移只在收尾做只读记录）。规则文件以任务开始时的现行文件为准，有用户后续修订则记录并落实，不静默混用。
2. **台账先行、断点续作。** 在 `tmp/<task>/<run-id>/`（工作区）和 `outputs/<task>-<run-id>/`（交付物）保存进度、备份与证据；上下文压缩后从台账继续，不重复覆盖已完成内容。每项完成声明必须对应真实证据（构建退出码、grep 清零、行号证据），不以"文件存在""有中文""自报完成"充当验收。
3. **只审不改与修复任务的边界。** 审读任务发现的问题只进报告；修复任务按最小必要改动落地。两者不得混跑（防审读 Agent 顺手改正文导致证据失效）。
4. **写盘自证。** 脚本辅助的修复必须实际写盘并复读验证；只改内存不落盘的"修复"会被后续轮次覆盖回归。每轮新反馈先复扫上轮已修项。
5. **check-deps ≠ 构建成功；HTML 构建成功 ≠ 正确。** 构建脚本放宽了中文 IDREF 校验，链接与结构须独立检查。最终验收以实际 HTML + A4/US PDF 构建和页面抽查为准。
6. **技术事实以该版固定英文为准。** 不从新版倒灌功能、默认值、限制到旧版；不为跨版本统一抹平真实版本差异。
7. **提交、推送、发布须用户明确指令。** 常规可逆操作（备份、diff、构建、临时目录）直接推进。

## 高发陷阱（跨任务通用）

- **行号 ≠ 对应。** 中英不能按行号/文件名匹配；用章节 ID、表格 ID、英文原句、邻接段落定位。母本 + diff 不等于本版全读。
- **折行与内嵌标签造成漏检。** grep 探针用短语而非整句；考虑大小写、词形、换行、实体转义（`&lt;`）、`<term>` 独占行。
- **生成文件差异。** `GENERATED_SGML`（版本实体、SQL 功能表、错误码、关键字、等待事件表等）随源码生成；稳定源码包带生成表而 Git 源不带，不能把生成表缺失误报为功能删除，须用对应版本源码重建后再比。
- **保护区不可染。** `<programlisting>`/`<screen>`/`<synopsis>` 等代码块字面内容；标识符、输出、示例；SGML 标签、属性、ID、`linkend`、实体。发现其中错译单列问题，不顺手全局替换。
- **不整文件重译、不整体重序列化。** 只编辑已核实的文本区间；脚本应用前检查旧文本仍匹配；禁止解析后重新序列化导致空白/实体大面积漂移。
