# PostgreSQL 14—19 术语校准计划

> 历史准备计划：以下记录原 v2 全量校准的范围与流程。2026-09-09 的当前执行范围见 [ROLLBACK-9.md](ROLLBACK-9.md)，现用规范见 [ACTIVE.md](ACTIVE.md)。本文件中的 68 项、试点和安装冻结 refs 等历史安排不授权扩大当前九项回退，也不能覆盖现用规则。

## 本次准备的范围

正式执行将处理 `zh/14` 至 `zh/19` 的术语一致性。以 631 条最终定稿词表为规范，以最初原表至定稿的 68 条净变化为本次主要迁移集合，并处理这些概念在正文中的同义简称和相关用法。未改变的 563 条提供约束；不因个人偏好重新翻译它们。

本准备包没有修改中文 SGML、英文快照或现用词表。正式执行提示词在 `PROMPT.md`。`refs/` 提供完整定稿、631 条规则、68 条差异、别名和保留规则；`USAGE.md` 给出适用条件与豁免。`baseline/` 是实测只读盘点，不能当作已经完成的语义校准。

顶层 Makefile 的 `ZH_VERSIONS` 默认只有 `14 15 16 17 18`，因此默认批量命令会漏掉 19。历史提示词还写有 `zh/<小版本>` 和“只翻译英文差异”等旧规则，不能照搬。本次必须原地编辑中文大版本目录，并检查历史正文中的术语，不以英文最近是否变更为筛选条件。

## 工作单位与台账

先把工作拆成九个词族，具体清单在 `families.json`。每个词族一次覆盖六个大版本。试点选正则转义与 pg_trgm；随后处理聚合函数、标识符、复制等上下文要求更高的词族。起始路径只用于快速定位，不能作为扫描白名单。

台账分两层：

1. **词条 × 大版本覆盖矩阵**：至少 68 × 6 = 408 个单元，另登记必要的同族衔接项。每格记录已审阅的英文和中文范围、候选处数、处理结果、豁免及未决项。准备包中的 408 格目前全部为 `PENDING_CONTEXT_REVIEW`。
2. **跨版本语义位置台账**：每个概念位置建立稳定的 `unit_id`，保存该位置在六版的对应路径、锚点、英文证据、修改前后片段、译法与处置。一个词条在同一文件出现多处时必须分别覆盖，不能以“这个文件改过了”代替逐处校准。

词条覆盖矩阵不能替代语义位置台账；所有适用位置都结案，才能把词条标记完成。每次改动都应能追溯到词条 ID、英文含义和六版对应情况。

仓库当前忽略 `tmp/` 和 `en/`。现用术语表位于忽略目录，因此仅看 Git diff 不足以证明词表安装与备份完成；应另外记录 `tmp/ref` 前后文件、哈希及逐项差异。冻结的 `refs/` 提供不依赖临时目录的完整交付。

## 检索与编辑方法

先使用 `rg` 或等价只读工具生成候选，再打开上下文核实。英文检索需考虑大小写、单复数、连字符、跨行、内嵌标签与实体。中文检索需覆盖定稿前后的不同表述，例如聚合状态中的简称“转换函数”，不能只搜完整旧词“状态转换函数”。

`scripts/preflight.py` 可以重跑；它生成 SGML 清单与哈希、版本映射、词条/版本候选矩阵、按文件汇总的命中位置和样例。它刻意不编辑正文，也不声称完成语义对齐：保护区、代码、注释及同形异义都可能命中；跨内嵌标签和未知别称也可能漏检。匹配中被同条最终中文完全包含的旧译子串会被略去，以减少“命令标识符”中“命令标识”的假阳性；只改英文的条目不把中文存在当作缺陷。

“主”不做单字旧译替换；“结构”“流复制”“日志序列号”等高歧义候选从英文对象反向确认。优先长词组，再审单词和短语。可自动化发现、分组、记录和检查；实际替换必须基于已核实的可翻译文本区间。

六版英文原句完全一致时先确定一次规范词语改法，再应用到各版对应中文；只相近时复用术语，不复制段落。文件移动或拆分时检查 ID、邻段及英文全文；同名文件不存在不能直接标为不适用。中文独有旧文件和英文独有新文件需要判断是否被本版书籍实际包含，再选择历史基准或登记缺失，不以路径差异自行删除或补译整章。

本地盘点以 SGML 为主。如果源文件通过实体引用其他格式的正文，或图像中存在本次涉及的可见中文标签，也要列入范围并逐项处理；不可因为扫描脚本只枚举 SGML 而宣称所有文档内容均已覆盖。生成的 HTML/PDF 只用于验收，不直接修改。

## 试点应验证的具体情况

- `func.sgml` 中字符项逃逸等旧译，在标题、firstterm、正文均改为对应转义术语；`\135` 等字面序列原样保留。
- `pgtrgm.sgml` 中三元组改为三字符组，但示例中的引号、空格填充、数组、运算符、函数名和索引类名不变。
- 对照 `xaggr.sgml`、`ref/create_aggregate.sgml` 及 `parallel.sgml`，确认“组合函数”“状态转换函数”“前向转换函数”等可由同一词族处理；不得波及类型转换函数。
- 以 `protocol.sgml` 中正确的“流复制协议”为反例，证明流程不会把所有流复制都改成流式传输。
- 对六版 `ddl.sgml` 的 secure schema usage pattern 检查例外条件，统一术语的同时保留各版本权限模型差异。

## 验收

### 内容验收

- 68 个净变更词条及必要衔接项都有逐版结论；原表与最终表的英中变动范围保持可追溯。
- 每个新增或修改的中文术语都能指向同版英文；没有新增技术事实、删除例外或回移新版本行为。
- 旧译残留要么完成校准，要么有已审定豁免；“搜索结果为零”不能单独作为完成证据。
- 新译也必须反向查验：重点查“流式传输”“主库”“结构体”“不记录 WAL”“状态转移函数”等是否进入错误语境。
- 所有跨版本语义位置有六版处置。`BLOCKED_EVIDENCE`、待核实版本缺失或待复核词条不能当作完成。

### 源码与结构验收

- `git diff --check`；按备份基线检查本任务 diff，区分已有 dirty 内容。
- 比较前后 SGML 标签、属性、实体、声明、注释和保护区内容，尤其 `id`、`linkend`、代码、输出及转义序列；保留用户原有的结构差异。
- 不使用整文件格式化或整本重序列化；新增的非术语措辞变化必须有必要的语法理由。
- 通过书籍的真实构建链验证实体展开、DTD、链接和输出；不能把独立 SGML 片段交给没有上下文的普通 XML 解析器后据此判断整个文档损坏。

### 构建验收

显式枚举 14、15、16、17、18、19，逐版调用 `make -C zh/<大版本> html`。逐版调用 `make -C zh/<大版本> pdf PAPER=A4` 以及 `PAPER=US`；可用 `BUILD_OUT` 和 `PDF_OUT` 把产物放进本次独立运行目录。不要依赖默认只覆盖五版的 `make all`。

如使用顶层批量 PDF 入口，必须显式传 `ZH_VERSIONS="14 15 16 17 18 19" PAPERS="A4 US"`；若执行前 Makefile 已变，先核对实际入口。记录每版每种格式的命令、退出码、日志、产物路径；构建失败记录首个根因错误。查看六版有改动的代表 HTML 页面和 PDF 标题、正文与索引，发现中文排版问题后只修与本次改动相关的部分。

构建可能调用缓存中的上游源码、下载缺失依赖和生成中间文件。使用本版 `PG_VERSION` 固定的版本；记录下载/依赖问题，不把失败解释为词表错误。修复常规本地环境问题后重跑必要检查；无法完成时保留已完成成果并明确剩余验收项。

## 交付与续跑

每完成一个词族，更新台账、剩余任务和本次 diff 检查结果。持续任务中断或上下文压缩后，从台账与实际文件状态继续；不要只凭上一段聊天的完成声明重复覆盖。

最终交付：正式启用的完整词表与配套规则；六版正文修改；按词条与版本统计的处数/文件数；跨版本语义位置台账；豁免清单；未决项；六版 HTML 和两种 PDF 的结果。检索命中数、实际修改处数和文件数分别统计，不能互换。

本任务默认交付本地修改与可审阅 diff。提交、推送和发布按后续明确指令办理，不应成为本地校准的等待门槛。
