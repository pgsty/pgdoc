## 目标与范围

对 PG 14、15、16、17、18、19 六个大版本的中文文档，找出仍使用旧术语或不一致同义表达的位置，对照各版本英文确认含义后，统一为最终定稿译法。每当修改一个版本的某个概念位置，必须核实另外五个版本的对应位置，并在所有适用版本采用相同的规范术语。

一致性按技术概念判断，不能为追求中文逐字相同而覆盖各版本的功能差异、权限条件、索引限制、参数、代码、数值和 SGML 结构。版本没有该功能时不得回移功能。这个任务不依赖英文最近有无改动；旧增量翻译提示词中的“只处理英文 diff”不适用于此次术语校准。

以 `refs/glossary.tsv` 的 631 条定稿作为统一词表，以 `refs/changes.tsv` 的 68 项净变化为主要迁移集合，并处理它们在同义上下文中的简称、单复数和相关用法。其余未改词条提供规范，不重新展开一轮个人偏好的译名审查。中途曾修改但最终回滚的词条，以定稿为准。

### 1. 固定基线并启用规范

记录 Git HEAD、分支、dirty 状态、当前规则哈希及六版英文来源。保护所有人工修改；不要清理工作树、重置文件或覆盖已有输出。在 `tmp/terminology-calibration/` 下自行创建一个唯一运行目录，持续保存备份、台账、日志和断点；不用为目录命名或常规执行步骤再次询问我。

运行准备包中的只读盘点脚本：`python3 plans/terminology-14-19/scripts/preflight.py --repo /Users/vonng/pgsty/pgdoc --out <本次运行目录中的全新 preflight 子目录>`。自行填入已创建的运行目录；脚本拒绝覆盖旧目录。核对准备后的变化；如果来源更新，记录新旧映射并以与当前中文实际匹配的英文为准，不能仅凭文件名最大就自动升级。

在改动前备份中文目标文件和 `tmp/ref`。正式安装规范时，对原词表、冻结定稿与现用词表做三方比对：现用仍等于最初原表时可直接采用定稿；已等于定稿时不重复修改；后来人工新增的条目和无关调整保留；有冲突时逐项核实，不能静默覆盖。将最终词表及配套规则安装到 `tmp/ref/glossary.tsv`、`tmp/ref/glossary.rules.tsv`、`tmp/ref/glossary-aliases.tsv`、`tmp/ref/terms-to-preserve.tsv`，确保本次流程实际读取它们，并按现行译风要求记录到 `tmp/ref/change.md`。不把所有缩写粗暴加入排除表来代替条件规则。

`tmp/`、`en/` 当前被 Git 忽略；需要另存规则安装前后的哈希和差异，不能仅凭 Git diff 认定输入已生效。

### 2. 全量发现与跨版本对齐

按 `families.json` 组织工作，每个词族覆盖六版，不按大版本各自独立决定译法。起始路径只是检索入口，实际必须搜索六版全部相关正文，包括 ref、发布说明、词汇表、索引、标题、表格和图注；被包含的其他正文源与图内可见中文也要登记。历史发布说明的自然语言不能整篇跳过。

旧中文、旧英文词头、批准的别名、常见变体与英文概念双向检索。考虑大小写、词形、换行、内嵌 SGML 标签和实体造成的漏检。对“主”“结构”“流复制”等高歧义词从英文反向定位，不能据中文字符串直接替换。

建立两层台账：68 × 6 的词条/版本覆盖矩阵，以及每个实际概念位置的跨版本语义台账。参考 `templates/unit.json` 与 `templates/exception.json` 的字段，但模板不是审查结果。每个语义位置保存词条 ID、文件与稳定锚点、该版英文证据、中文修改前后、六版处置、核查结果及理由。

对齐优先使用相对路径、章节/表格 ID、英文原句与邻接段落。英文原句相同的先确定一次规范改法，再应用到所有对应中文；原句部分相同的只复用相同概念的术语。不能整文件复制、按行号硬套、仅因文件名相同就断言对应，或者因同名文件缺失就标记版本不存在。

### 3. 试点后按词族完成迁移

先用正则转义和 pg_trgm 做六版试点，验证可翻译文本定位、代码保护、跨版本同步和台账流程。检查通过后继续处理全部九个词族。聚合函数词族要一起处理合并函数、状态转移函数、逆向状态转移函数，以及确指同一操作的简称，覆盖 xaggr、CREATE AGGREGATE、并行查询等相关位置。

每次只编辑已经核实的文本区间。脚本只能辅助已确定的修改，应用前检查原文本仍匹配；产生 diff 后逐项审阅。保持 SGML 标签、属性、ID、实体、注释、代码、名称、输出和示例不变。不要整体格式化或重序列化文件，也不要扩写无关背景或顺手修改与术语无关的翻译。

每完成一个词族就闭合所有适用版本的对应位置，检查结构和保护区，更新台账及剩余任务。若采用并行工作，按词族划分、共享同一规则与台账；重叠文件串行整合，不能让不同版本分别自行选择译法。遇到某项证据不足，保留该项的原内容并登记未决，继续处理其他独立项。

### 4. 必须遵守的关键语境边界

- streaming replication 仍为流复制；不能把所有流复制改成流式传输。
- master 只有复制角色语境为主库；master key 等其他组合单独判断。
- 聚合状态的 transition function 采用转移词族；类型转换函数和触发器过渡表不能连带替换。
- pg_trgm 的 trigram 是三字符组；其他 tuple、三元关系或词级 NLP 语境不套用。
- skew 依完整语义区分倾斜、偏度、时钟/读/写偏差。
- `cid`、`pg_lsn`、`txid`、`TimeLineID` 等保留实际名称，规范的是中文说明；不能把一般日志序列号都改为日志序列号类型。
- pd_checksum、pd_flags、START WAL LOCATION、TimeLineID 等词头勘误不授权自动改写代码或原始输出。旧英文拼法可用于检索，引用与变量拼写须忠于本版原文。
- B-tree 概念在说明性正文中译为 B-树；btree 访问方法名及 BRIN 操作符类标识符保持原样，中文概念与实际标识符分别判断。
- HOT 的中文主译仍为堆内元组；不重新改成仅堆元组。索引条件、汇总索引例外和历史内部实现逐版核对。
- unlogged 限定普通数据变更不记录 WAL，不能改写成所有操作都不产生任何日志。
- `<link>`、`<emphasis>`、`<firstterm>` 内的自然语言可以校准；属性、链接目标及代码类标签的字面内容不能改。
- 别名只帮助定位。适用正文仍以定稿主译为目标，不能用“别名表里有”作为继续混用旧主译的普遍理由。

具体条目以 `USAGE.md` 和逐条规则为准。规范译名之外允许保留合法缩写与必要语法变体；一致性不要求六版整段中文逐字相同。

### 5. 全量审计与验收

对全部修改做反向审计，不能只抽样：

1. 旧译残留审计：每处应改项完成校准，每处保留项有明确上下文理由。
2. 新译误用审计：重点检查新词是否误入代码、输出、异义语境或不适用版本。
3. 英文驱动漏项审计：检查未知旧译、简称、跨行/跨标签等导致的中文搜索漏项。
4. 跨版本审计：每个语义位置六版均有处置，每个词条/版本单元覆盖了所有适用位置。
5. 结构保护审计：对照改动前基线核对 SGML、ID、linkend、实体、注释和所有保护区；运行 `git diff --check`，区分原有问题和本次新增问题。
6. 真实构建：显式对 14、15、16、17、18、19 运行中文 HTML 与 A4、US 两种 PDF 构建，记录每版每种格式的命令、退出码、日志和产物。调用 `make -C zh/<大版本> html`、`make -C zh/<大版本> pdf PAPER=A4`、`make -C zh/<大版本> pdf PAPER=US`，自行逐版展开；可用 BUILD_OUT/PDF_OUT 隔离本次产物。顶层批量入口必须显式包含 19。
7. 查看六版相关代表 HTML 页面与 PDF 的标题、正文、目录和索引显示。`check-deps` 通过不是构建成功；实际构建失败要定位首个根因并如实记录，不能因缺少依赖跳过全部内容审计。

豁免要注明词条、版本、稳定位置、英文证据、理由和适用范围。可接受类别包括保护字面形式、异义语境、合法形式、忠实引用、已核实版本不存在、已核实未被书籍包含的孤立文件。缺少证据、只写未找到或未完成核实属于未决，不算完成。

### 6. 交付

交付实际校准后的六版正文、正式启用的完整词表和配套规则，以及可审阅 diff。另提供：按词条和大版本统计的实际修改处数及文件数、跨版本位置台账、豁免清单、未决项、保护区和结构检查结果、六版 HTML/A4/US PDF 的真实验收结果及产物位置。

保留逐批进度与可恢复断点。任务长或发生上下文压缩时从台账继续，不重复覆盖已完成内容。只有所有适用项完成、跨版本差异均有依据且必要验收通过，才可称全部完成；有未决或构建失败时明确列出剩余事项。
