## 第一阶段：固定源码、建立底稿、生成完整 diff

### 1. 固定可复现的输入

记录当前 Git HEAD、工作区状态、中文基线和所有现用规则的 SHA256。复制中文源文件及规则到本轮独立快照，核对复制前后来源未发生漂移；后续阶段必须使用这份一致的固定输入。不要从 Git HEAD 导出中文来替代带人工修改的当前工作区。

官方来源可使用：

- `https://git.postgresql.org/git/postgresql.git`
- `https://github.com/postgres/postgres.git`
- 版本核对参考：`https://www.postgresql.org/docs/devel/`

取得完整源码或保留足以重建文档及其生成表的完整源码缓存，再把该提交的 `doc/src/sgml/` 导入 `en/20/`。翻译对象是源码，不是抓取的 HTML 页面。若使用源码归档，校验归档并记录其真实内容来源；不能把查询到的分支 HEAD 写成无法证明相符的日更 snapshot 的提交号。

同时核对 `en/18.6/` 的来源和本地偏差。需要时用官方 18.6 源码包与校验文件或对应 Git tag 验证，保留本地已有英文目录，不静默覆盖。开发网页与 Git HEAD 可能不同，以本轮选择并验证的固定源码提交为准。若拿到的不是 PG20，先解决来源问题，不能仅将版本标签改成 20。
