## 四、先完成四版文件差异与继承骨架

递归比较完整文档源树，包括顶层、子目录、命令参考、图片、实体及包含入口、样式、脚本和其他资源。先生成四版共同的路径矩阵，再分别保存完整原始 diff 和逐文件 diff；新增、删除文本也必须有原文证据，二进制及类型变化以哈希和说明记录。

统一使用“左侧为 PG14.24，右侧为历史目标”的方向，并采用以下含义，避免把时间上的新旧与 diff 的左右混淆：

| 英文路径或片段关系 | 对目标中文的处理 |
|---|---|
| 两侧相同 | 原样复用 PG14 中文，保留人工格式 |
| 仅 PG14 有，历史目标没有 | 从该目标底稿移除；先检查是否在目标其他位置存在 |
| 仅历史目标有，PG14 没有 | 恢复历史内容；先检索可复用译文，无可用基础的部分才首次翻译 |
| 两侧均有但内容不同 | 以目标英文为准局部回推，保留共有部分的中文 |
| 重命名、搬移、拆分或合并 | 先映射并保存中文片段，再按目标结构迁移，内部差异另处理 |

“新增”不等于新功能：反向比较中，它可能是后来被移除的旧功能；“删除”也不意味着要删除旧版本所需的内容。文件不存在不证明内容不存在，ID 相同也不证明正文语义未变。

四个中文目标分别从冻结的 PG14 源文件初始化，继承必要图片、项目中文样式和构建配置，记录复制来源与哈希。按实际构建依赖排除 HTML/PDF/FO、展开 XML、缓存和派生文件；不能仅凭扩展名排除上游源资源。

在正文翻译前完成四版文件动作和结构骨架：安排目标独有路径，迁移可复用中文，维护包含链；所有删除先确认迁移来源已保存。历史独有正文可处于明确的待译状态，不能因文件已经存在就标记完成。结构改变导致的段落增删和文字变化留给内容阶段，不用机械删除来凑路径一致。

发布说明按每版真实源码及包含链处理，不把 PG14 发布历史直接改标题后沿用；目标手册自带的更早历史记录仍属于该手册，不等于另外创建 9.x 中文版本。项目 Makefile、中文 CSS/XSL 等定制单列，不能混入正文翻译清单或被上游文件直接覆盖。

文件阶段交付逐版 `inventory.tsv`、`changes-summary.tsv`、`full.diff`、`diffs/`、`structural-map.tsv`，以及一份四版路径矩阵和中文继承清单。核对每版的基线/目标路径数量等式，检查完整 diff 能重建目标英文树；结构重命名视图不能抵消原始路径证据。实际文件清单和统计由本轮生成，不引用 PG19/20 的旧清单。

## 五、再按跨版本语义单元批量处理内容差异

### 1. 从文件内部 diff 形成可定位单元

为每版全部原始 hunk 建立唯一 ID，区分正文、结构、字面示例、格式、资源及生成内容。逐文件处理，但按完整段落、列表条目、表格行或相连语境形成语义单元；一个文件可以包含多种动作。纯移动、注释、空白和代码变化不计为首次翻译。

用章节 ID、包含关系、标题、邻接段落、表格/列表结构定位 PG14 中文，分别记录中英文路径、位置、文本与哈希，不能套用英文行号编辑中文。迁移后仍有内部差异的片段，继续比较内容；不能因结构映射成功就跳过正文。位置匹配只是候选，写入前核对实际语义与边界。

### 2. 四版共享一套译文决定

将四版目标英文中的相同内容归为共用翻译组，关联各版本的具体位置、hunk 和可复用 PG14 中文。**同一英文、同一语境、同一含义必须使用同一份中文。** 一次确认，应用到全部适用版本和位置；不让四版分别独立定译，也不必等一整版完成后才开始另一版。

- 优先继承 PG14 中英文含义未变的中文，包括搬移或重新组合的片段；不因历史目标更旧就重写共有内容。
- 历史目标独有内容先查项目已有译文。可用其他版本或本批已经确认的译文，但必须同时核对其对应英文与目标英文，记录来源；不能整树替换 PG14 底稿，也不能把未审核候选当成定稿。
- 一个组内若只有部分句子相同，只复用共同部分；函数签名、数值、默认值、条件、支持范围和版本专属说明分别保留。相同词形但含义不同的语境应拆组，不为表面一致改变技术事实。
- 辅助归并可以忽略纯排版、注释或另行保存的非语义结构差别，但不能丢弃代码、标识符、数字、否定/条件或链接含义。各版自己的标签、ID、链接、实体和发布说明提交引用分别维护，原始 diff 始终保留。
- PG14 共有内容如果已有译法冲突，按对应英文与当前规则确定有依据的共用译文，在目标中记录必要订正；不回改 PG14，不把这一例外扩大为审美润色。

本批按“同一文件或关联主题在四版的差异集合”拆任务，并协调跨文件的同一术语族。共用译文由一个决定记录管理，每个目标文件在同一阶段有明确的修改责任；任务粒度可调整，但不能产生重复修改或四份互不关联的术语决定。

### 3. 执行边界与术语

只翻译目标英文相对 PG14 真正新增或变化的可翻译文本；未变化的中文原样继承。恢复旧行为、旧限制和旧例子是本任务的一部分，不用现代用法“修正”历史原文。若目标确有缺文或错配，给出对应英文证据并在目标内最小修复，单列为基线修复。

按以下顺序判断：**目标版本英文含义 → exclude.tsv 与适用的字面保护 → glossary.tsv 及逐条规则 → style.md → 稳定既有译法。** `glossary-aliases.tsv` 用于检索和消歧，不是批量替换字典；不将旧复审候选整体覆盖当前 `tmp/ref`。

继续使用已确认的 B-树、默认 B-树操作符类、以先提交者为准、以先更新者为准、整页镜像、首部数据、连接类型和方式、百分位点、插入值，遵守完整词条与语境，保留独立的“离散百分位数”等译法。适用时保持现行订正，例如区分 index vacuuming 和 index cleanup；不能把只适用于较新功能的说明套进旧版。没有收录的历史概念先核对同族译法，在本轮 `TERMS-NEW.tsv` 定稿并供四版共用，不重开既有词条的审美修订。

保护真实代码、SQL、命令、参数、路径、对象名和输出的字面形式；目标英文有变化时同步为目标版本的原文。保留 PG14 字面内容不能成为保留新版本错误示例的理由。不要一概冻结所有内联标签中的文字：标题、可见索引、说明性占位符与注释等仍需按语境翻译。SGML 标签、属性、层级、实体和链接按目标源码必要差异同步，保留未涉及部分的格式。

不调用通用翻译 API 批量重译，不从网上拼接中文手册。必要技术查证使用对应历史版本的官方源码和文档。

## 六、任务表、台账和阶段顺序

文件盘点完成后，依据实测结果生成本轮 `PLAN.md` 和统一 `TASKS.tsv`，持续更新状态。执行顺序为：

1. 固定五份英文、PG14 中文及规则输入，保存已有工作。
2. 四版文件盘点、结构映射、底稿初始化及文件动作。
3. 建立共用语义组，按文件/主题批量完成四版内容差异。
4. 核对删改配对、包含链、引用、版本元数据、资源和生成内容。

这些是连续工作的阶段，不是要求每完成一阶段就等待用户再次批准。发现某项真实阻塞时保留证据并继续不依赖它的工作，未解决项不能伪装成完成。

任务表至少记录任务 ID、阶段、依赖、适用版本、目标文件、动作、hunk/语义组 ID、中英文来源引用、状态和验收要求。动作应区分继承、迁移/拆分/合并、移除 PG14 独有内容、恢复历史内容、局部翻译、结构/字面同步、资源/生成适配、项目定制和基线未决。

共用语义台账记录目标英文、PG14 英中参考、确认中文、四版适用位置与差异例外；每版每处实际应用再记录修改前后片段、来源哈希、规则依据、检查结果与未决原因。相同中文可共用，但每个版本都须有独立的应用和核验结果；“该版不适用”也要有理由。

全部原始 hunk 必须有处置，每个需要修改的语义单元恰有一个任务负责；生成内容的差异另列，不能抵消正文遗漏。覆盖率必须能由原始差异与实际源码独立核对，不能只查台账是否把自己标成完成。支持断点续作，续作先核对现有成果和后续人工修改，不重新初始化目标树。

## 七、验收与交付

### 源文与一致性

- 四版 authored source、包含链、资源和目录分别符合其英文目标；生成文件与项目中文定制列出可解释的差异。没有历史内容遗漏、错误删除或 PG14 独有内容残留。
- 全量文件、hunk、结构迁移和翻译单元均有实际处置证据；首次翻译、复用、部分复用、删除、纯结构及基线未决分开统计，不将候选数当作已完成译文数。
- 未变中文有继承哈希或片段映射证明，额外订正有必要性及英文依据。检查术语、标签/实体、重复及缺失 ID、包含文件、链接、可见索引、代码示例、数字、否定和版本条件。
- 对共用组检查四版中文一致性，同时检查版本专属差异没有被抹平。英文未变但存在必要基线订正的例外逐项列明；PG14 及其他版本的源文保持原样。
- 运行 `git diff --check` 和适合本轮内容的源文审计。已有构建脚本可能放宽中文 IDREF 验证，HTML 构建成功不能代替独立结构和链接检查。

### 实际构建与查看

每版使用自己的固定源码、生成规则和最终中文，实际构建 HTML、A4 PDF、US PDF，共 **12 项构建目标**。目标 Makefile 显示对应完整小版本，不继承 PG14 的版本标签；不修改现有顶层默认版本或发布目录来凑构建结果。

先检查当前构建链是否能验证并使用固定的归档包/源码，以及是否兼容旧版的 DocBook 和构建依赖。已有固定源码能力应复用；确有缺口时做最小兼容适配，不强制旧版具备 `meson.build` 等新文件，不将发布包伪装为 Git checkout，也不静默回退到其他源码。若修改公共脚本，验证现有调用兼容性，并在隔离输出中做受影响路径的冒烟检查。

保存实际命令、退出码、完整及内部日志、各版最终源码和产物哈希、产物路径。检查四版代表性的历史独有页、修改页、迁移页、目录/索引和链接；查看每版两种纸型的中文字体、代码、表格和分页。记录具体检查范围，区分继承诊断与新增问题，不宣称检查了未查看的页面。`check-deps` 只是依赖检查，不算构建完成。
