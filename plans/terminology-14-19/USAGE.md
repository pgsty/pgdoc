## 判断顺序

1. **先确定技术含义和版本。** 找到该中文段落对应版本的英文，确认对象、词性、领域和句法。术语表不改变英文表达的技术事实。
2. **先保护字面形式。** SQL、代码、名称、标识符及原始输出按现行 `tmp/ref/exclude.tsv` 与译风规范保留；即使两列词表给出中文释义，也不能因此翻译这些字面形式。
3. **按逐条用法选用现用译名。** `tmp/ref/glossary.rules.tsv` 是 `tmp/ref/glossary.tsv` 的必要解释，不是可选附件；同一术语的限制条件与译名必须一起使用。
4. **按现行译风调整最小语法范围。** 再应用 `tmp/ref/style.md` 和未受本次变更影响的稳定中文。允许为新词调整紧邻助词或词序，不能借机重写整段。

因此，操作次序是：版本英文语义 → 字面保护与排除规则 → 定稿词条及逐条条件 → 译风与必要语法。排除表决定哪些实际 token 保留，不代表遇到该字符串就冻结整段中文。显式任务授权本次历史正文术语校准；不受旧增量翻译流程“只处理英文 diff”限制。

`refs/exclude.tsv`、`refs/style.md` 是准备时的快照，便于追溯。执行前必须读现行 `tmp/ref/` 文件并检查差异；不要把快照倒灌覆盖后来的人工修改。完整词表的中文列既可能是正文译名，也可能是原文名称的中文释义。`保留字面形式=是` 不等于把所有既有中文解释改成英文。

正式应用排除项、标识符和词条时区分大小写、token 边界，并优先识别长词组。`CC` 与 `cc`、`JOIN` 与普通 join 不能混同。只读检索可以忽略大小写以扩大候选范围，但检索命中本身不构成替换依据。

## 三类条目的处理

| 条目类型 | 应如何使用 | 例子 |
|---|---|---|
| 正文概念译名 | 对照英文确认同义后，把旧译统一为定稿译名 | combine function → 合并函数；trigram 在 pg_trgm 中 → 三字符组 |
| 名称、缩写的中文释义 | 保留实际名称和缩写；中文定义、解释或已有展开式采用规范释义 | `cid` 不译，解释为命令标识符；`MVCC` 保留，中文展开式为多版本并发控制 |
| 英文词头规范化或勘误 | 改词表检索和别名记录；文档中真实字段、代码和引用拼写以本版英文为准 | `pg_checksum` → `pd_checksum`，不能在正文代码中无条件替换 |

已有首用引介方式可保留；仅在本次变更导致含义不清或该条规则确有必要时补足简短引介。不必在每段、每页重复添加英文括注。合法缩写与中文全称并存并不构成跨版本术语不一致。

## 可修改与必须保护的内容

- 可修改：可翻译正文、标题、表格说明、图注、脚注、命令参考页的自然语言描述、中文索引项和词汇表中的中文说明。`<emphasis>`、`<firstterm>`、`<link>` 内的自然语言并非一概不可译。
- 必须保持：SGML 标签、属性、层级、ID、`linkend`、URL、实体引用、声明、注释、条件包含语法、索引与命令参考页的结构。索引项可见中文可以校准，其结构和排序属性不擅自修改。
- 代码保护区：`<programlisting>`、`<screen>`、`<synopsis>`、`<literallayout>`、`<computeroutput>`、`<userinput>` 的字面内容。内嵌 `<literal>`、`<command>`、`<function>`、`<type>`、`<varname>`、`<filename>`、`<option>`、`<replaceable>` 等名称和占位符原样保留。发现其中既有内容明显错译时，单列问题，不能用全局替换顺带修复。
- SQL 示例、命令输出、错误信息、配置、路径、协议字段、类型名、函数名、参数名、人名、项目名和引用标题的实际字面形式不得因词表统一而被改写。保护范围按语义判断，不能只依赖标签。
- `en/` 是核对依据；本任务不修订英文，不同步新上游版本，不改构建版本号。原版本的技术限制、数字、异常条件和 API 差异必须保留。

编辑应修改原文件中的已核实文本区间。不能把整个 SGML 文件重新解析后整体序列化，导致空白、实体写法或属性顺序大面积变化。需要脚本辅助时，先产出逐处 diff；每个修改区间必须检查旧文本仍匹配，且未进入保护区。

## 必须结合上下文的重点条目

| 场景 | 采用方式 | 豁免或边界 |
|---|---|---|
| streaming / streaming replication | 前者依语境为流式传输或流式处理；后者仍为流复制 | 不把所有“流复制”替换成“流式传输” |
| master / master-slave | 数据库复制角色用主库、主库/从库 | master key 为主密钥；不得对单字“主”全局替换 |
| struct / structure | 说明 C 的 struct 时用结构体；代码关键字保留 | 一般数据结构或组织结构中的“结构”不应统一改成结构体 |
| state / inverse transition function | 聚合状态语境用状态转移函数、逆向状态转移函数 | 类型转换函数不改；触发器 transition table 仍为过渡表 |
| transition function 的简称 | 同一聚合机制中，按上下文将转换函数、前向转换函数等衔接为转移函数、前向状态转移函数等 | 不是新增独立译名；需确认回指同一个聚合状态操作，不能扩大到所有转换函数 |
| combine function | 合并的是部分聚合状态 | 不是合并最终结果值，也不是一般函数复合 |
| escape / escapes | 字符与正则表达式语境用转义 | escape analysis 等其他领域不逐字套用；所有转义字面序列保持不变 |
| trigram | pg_trgm 的字符级对象用三字符组 | 不修改 tuple、一般三元关系或词级 NLP trigram 的其他含义；示例字符串与填充空格不改 |
| peer group | 同等行组，以窗口 ORDER BY 键判定 | 不要求整行每列相等；没有 ORDER BY 的情形按该版英文解释 |
| skew | 数据或负载分布不均用倾斜 | 统计不对称性可能为偏度；clock/read/write skew 等按完整词组处理 |
| percentile(s) | 表示分布分位值时用百分位点，不限于 DDIA | discrete percentile 等完整词条仍为离散百分位数；区分输入 fraction、百分等级、百分比，函数名不改 |
| unlogged | 普通数据变更不记录 WAL 的关系 | `UNLOGGED` 不译；不推导为不产生任何服务器日志或所有操作均无 WAL |
| B-tree 与 BRIN 类族 | 数据结构概念用 B-树，默认 B-树操作符类；撤销正文概念必须保留英文的规定 | `btree`、`USING btree`、`btree_gist`、`*_bloom_ops`、`*_inclusion_ops` 等真实标识符、代码、输出及文献标题保持原样 |
| full-page image / backup block | WAL 中的 full-page image 及明确回指用整页镜像、镜像；backup block 仅在确指该对象时衔接 | 前映像、后映像及其他 image 词条不随之回退；函数、配置、输出保持实际形式 |
| header data | 首部数据 | 不扩展替换页头、元组头或 PageHeaderData 等名称 |
| Join Types and Methods / Value Insertion | 对应标题采用连接类型和方式、插入值 | 句中按对象和语法处理，不全局替换和/与、方式/方法或将值插入 |
| HOT | 中文主译仍为堆内元组，优化行为写 HOT 更新；保留既有首用规则 | 仅堆元组是检索别称；HOT 的索引条件和汇总索引例外按各版本英文，不从 PG18 复制到旧版 |
| pg_lsn、cid、txid 等 | 规范中文解释，保留真实类型或标识符 | 不把每个“日志序列号”补成“日志序列号类型”，须确认英文指的是类型 |
| pd_checksum / pd_flags | 词表已按页头字段勘误，中文释义不变 | 原文中的 pg_checksum、pg_flag 先核实所指，不能当作合法代码别名全局替换 |
| TimeLineID | 类型名按该版英文/源码，中文为时间线 ID | `timelineId` 等变量必须保留实际拼写；不以大小写相似判为同一个对象 |
| first-committer-win / first-updater-win | 恢复原词头及以先提交者为准、以先更新者为准；wins 形式可用于检索 | 文献与代码中的实际拼写保持原样，具体裁决规则以来源及版本为准 |
| savepoint / wraparound | 沿用现行词头和别名规则 | 不因词头规范自动改写来源或代码中的连字符等实际拼写 |
| START WAL LOCATION | 中文释义为 WAL 起始位置 | 备份标签及输出字段按本版英文原样保留，不对 START WAL 的每个出现补词 |
| io_in_progress_lock、buffer table 等内部术语 | 只在该版本确有对应结构或历史说明时应用 | 词表中的 PG18 实现说明只是有版本范围的依据，不是 PG14—19 通用实现承诺 |
| log compaction、Oracle index cluster | 在各自技术语境使用日志压实、多表索引簇表 | Kafka、Oracle 或书籍专属条目可能未出现在 PG 手册，不为凑覆盖增加内容 |
| secure schema usage pattern | 模式的安全使用方式；该段相关 usage patterns 衔接为使用方式 | 不把 schema 的模式改掉，不批量替换所有 pattern 或所有使用模式 |
| 简称与正式名称 | 标题、定义和术语项采用外部排序、快速排序等完整名称 | 原始输出中的 quicksort 保留；自然语言中确有意使用已引介简称时可保留并记录理由 |

## 跨版本一致性的判定

一致性是“同一技术概念采用同一个定稿译名”，不是六版整段中文逐字相同。不同版本可能采用缩写、单复数、不同句式、不同例外和不同 SGML 结构；这些差异保留。若同一概念在某版用了全称、另一版用了合法缩写，只要展开式和用法一致即可。

每个已修改位置都必须检查另外五版的对应概念。优先使用文件路径、稳定的章节 ID/表格 ID、英文原句及邻接段落来定位；同路径、同行号本身不能证明对应。源句一致时复用词语级改法，源句相近时只复用已确认的同义部分。不得整章复制、覆盖版本差异，也不得给缺少该功能的旧版补上新功能。

## 豁免记录与未决项

每个候选最终必须有明确处置：修改、已经规范、保护字面形式、异义语境、合法来源/简称、已核实版本不存在。豁免至少给出词条 ID、大版本、文件和稳定定位、中文片段、对应英文证据以及理由。支持某项豁免的证据不能只写“历史用法”“未找到”或“感觉更自然”。

- `PROTECTED_LITERAL`：代码、名称、输出等需要原样保留。
- `DIFFERENT_SENSE`：中文或英文相同但不是该词条的技术含义。
- `ACCEPTED_VARIANT`：定稿允许的缩写、语法形式、简称或有必要保留的来源用词。对本任务正在校准的同义正文不能仅凭“别名表收录”继续混用旧主译。
- `VERSION_ABSENT_VERIFIED`：该版英文确无该概念或功能，且检查过章节移动、改名、拆分及同义表达。缺少同名文件或零字面命中不足以成立。
- `HISTORICAL_QUOTE`：必须忠实保留的原始输出、引用或名称；发布说明的普通中文叙述不因此整篇豁免。
- `ORPHAN_NOT_INCLUDED`：实测确认该文件不在本版书籍的实体/包含引用链中，且对应英文快照没有此文件。登记路径与包含关系证据，保留原文件；不能通过补入引用或引用较新版本原文来制造对应位置。
- `BLOCKED_EVIDENCE`：找不到可靠英文对应、基线漂移或含义仍有冲突。它是未决项，不是通过项；继续处理其他独立条目，最终如实报告。

现用 `tmp/ref/glossary-aliases.tsv` 只辅助检索和一致性检查；`refs/aliases.tsv` 是旧快照。词头勘误不是代码替换规则；已撤回译法的记录也不是继续保留应回退正文的豁免。合法保留必须落到具体语境。
