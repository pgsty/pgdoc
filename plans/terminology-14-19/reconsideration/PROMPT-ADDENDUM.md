## 何时改，何时保留

逐项读取 `decisions.json` 的类别和理由：

| 类别 | 数量 | 词表处理 | 正文处理 |
|---|---:|---|---|
| R：恢复原表首选 | 9 | 恢复原词条，撤销过度保护或排除原译的条件 | B-树的有效中文地位应恢复；只有确实需要回退的对应位置才改。整页映像、头部数据、百分位数等本身也可成立，不能反过来把新译全列为错译 |
| O：撤销强制迁移 | 16 | v2 可继续作为全称或首选，认可原译 | 正确旧译不要求清零；正确且已跨版一致的新译也保留。不要制造一轮反向写法统一 |
| C：保留并限定语境 | 13 | 保留候选释义，条件是词条不可分割的一部分 | 先确定对象与完整词组；发现不当扩写才修正。已有正确应用不回退 |
| K：保留修订 | 30 | 保留有含义、类别或可读性收益的调整 | 对照各版原文落实。词表改进不等于所有旧中文出现都是错误，也不授权全局替换 |

这里所说“原译可以接受”，要求它在具体段落中含义明确、语法正确。例如“事务标识”可接受，不能据此认可一个把事务标识与命令标识混为一谈的句子。

## 字面保护的实际边界

- 普通概念 B-tree 可以译为 B-树，B 树是可接受排版；访问方法名 `btree`、`USING btree`、扩展名 `btree_gist` 和函数、输出中的实际名称保留。不得凭英语外观或出现频率，把普通概念升级为必须保留英文的专名。
- 缩写保留规则针对原文已经出现的缩写。首用可采用“中文（缩写）”；原文使用完整概念名时，不把现有中文强制换成英文缩写。`exclude.tsv` 中实际字面项继续受保护，不能将缩写条目的保护扩大到整个中文概念词族。
- BRIN 的 Bloom、Inclusion、Minmax、Minmax-Multi 条目保留补出的“操作符类”；真实 `*_ops` 名称必须保留。说明性类别名称可以解释其含义，不能从代码名的保护推出同形普通单词永不翻译。本轮没有另行改动这四项已有的英文类别名称。
- `first-committer-win`、`first-updater-win` 与 `wins` 形式按来源保留；不能把检索别名处理当作纠正作者正文或代码的授权。
- `pd_checksum`、`pd_flags`、`TimeLineID`、`START WAL LOCATION` 的词表勘误只针对已确认对象。相似变量名、工具名或输出片段必须分别核对；英文词头勘误与中文写法统一分开记录。

## 防止语境被缩窄

| 原文实际对象 | 合适表达 | 不可机械推导的表达 |
|---|---|---|
| master server / master key | 主服务器 / 主密钥 | 都补为主库 |
| streaming replication / streaming execution | 流复制 / 流式执行 | 都替换成流式传输 |
| parameterized path / parameterized index path | 参数化路径 / 参数化索引路径 | 都加上“（索引）” |
| DTrace probe / 后续已限定的 probe | DTrace 探针 / 探针 | 每个探针都加 DTrace |
| data skew / clock skew | 数据倾斜 / 时钟偏差 | 把所有偏差改为倾斜 |
| 程序名 postgres / 产品简称 Postgres | 按各自对象保留写法 | 仅据首字母大小写判错 |
| 进程 walreceiver、walsender / 泛指接收或发送组件 | WAL 接收进程、WAL 发送进程 / 接收器、发送器等 | 对组件一律补进程 |

聚合、正则、pg_trgm、UNLOGGED、BRIN 等已有技术限制继续有效。特别是“日志已明确指 WAL”与“所有操作不产生日志”含义不同；分位值、百分等级和输入比例也不能靠统一几个中文字替代技术校对。
